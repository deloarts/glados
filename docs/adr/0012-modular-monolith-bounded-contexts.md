# 0012 the backend is a modular monolith of seven bounded contexts

- Status: accepted
- Date: 2026-11-02

## context

[ADR 0001](0001-hexagonal-architecture-async-io.md) layered the backend inward, and guard tests keep the layers, the permission order and the reconciler order honest. Nothing kept the business areas apart: any use case could import any other area's entities, repositories or use cases, so a change to one area could break another without anyone noticing. A count of the imports between use-case packages showed most of the coupling running in one direction already, with a few places against it, such as the bought item package holding demand use cases and project use cases reading the work planned on a project. Splitting into services would have bought separate deployments the system does not need at the price of distributed transactions it cannot afford, since the lifecycle reconciler locks across demands, orders and lots in one transaction.

## decision

The backend stays one process with one database and is cut into seven modules, its bounded contexts: Platform, Catalogue, Workspace, CAD & external data, Planning & fulfillment, Quality & documents and Operations. Planning & fulfillment is one module because the reconciler is one transaction boundary. CAD & external data is named after its job, not a vendor, so a second CAD source becomes a second adapter.

Each module declares the modules it may depend on, and the declared graph has no cycles. Code without business meaning that every module uses, such as the clock, changelog entries, base classes and the lifecycle action names, forms a small shared kernel that depends on nothing. Each module has one public API: its `api.py`, which re-exports the ports it owns for others to implement or extend, and its named interfaces. Those are its domain entities, events, value objects and errors, the rules other modules apply (`domain/policies/`), its DTOs and the mappers that produce them, its query facades and command facades (`application/facade/`), and its ports outside its repositories, among them narrow query ports with the read methods other modules call, which its repositories satisfy as they are. Entities are published read-only: snapshot copies of items would repeat the entities field for field, so other modules read the entities and change them only through the owning module's commands. Because the modules share one database, other modules' persistence adapters may use a module's ORM models and row mappers, and other modules' routes may embed its API schemas. A higher module may not reach into a lower one's repositories, use cases or services. A lower module reaches a higher one through a port it owns and the higher one implements, through an event, or through a registration the higher module makes at startup. Platform in particular never names a module: settings sections, event types, notification rules and the work a user delete must do are registered or implemented by the modules that own them.

The folders are the modules: `src/modules/<module>/` with the hexagonal layers of ADR 0001 inside, next to `src/shared_kernel/`, the read tier in `src/read/` and the composition root in `src/bootstrap/`. import-linter enforces the layers, the declared dependencies and the public APIs; an exception may be listed with its reason while a fix is under way, and an entry that matches no import fails the run. `api.py` re-exports ports only, not every public name: a re-export of everything would make each importer load the whole module, and would let a ports module reach application code through it.

## consequences

An import against the rules fails a check instead of surfacing in review. When the decision was implemented, no exception was left: every module imports only its declared dependencies and only through their public APIs. A module's declared dependencies say what it builds on, and a dependency it stops using must leave the list. Foreign keys between modules stay, because the boundary lives in the code, not the schema. The folder move was done before the first release, when no released branch needed fixes merged across it. Import paths are long, so the line length check allows 120 characters, while the formatter still wraps code at 100. The rules are in [CONTRIBUTING.md section 1.5](../CONTRIBUTING.md#15-bounded-contexts).
